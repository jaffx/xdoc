## 分层与层前缀

服务端按模块分目录，模块内按层分文件。

```text
src/server/
├── index.ts      组装点：监听、鉴权、路由分发、静态资源
├── context.ts    组装点与各模块的契约
├── bootstrap.ts  启动时装载空间
├── kernel/       共享地基，不属任何模块
├── <模块>/       ctrl · service · manager · dao（+ 可选的 types）
└── ../mcp/       与 HTTP 平级的另一个入口
```

### 文件 → 层（本项目只在此处声明一次）

| 组织单元 | 层 |
| --- | --- |
| `<模块>/ctrl.ts` | 入口 Controller |
| `<模块>/service.ts` | 业务 Service |
| `<模块>/manager.ts` | Manager |
| `<模块>/dao.ts` | 存储 Dao |
| `<模块>/types.ts` | 契约 / 类型，不划层 |
| `kernel/`、`index.ts`、`context.ts`、`bootstrap.ts`、`../mcp/` | 不属任何模块的层 |

新增模块时对照此表。一个类属于哪一层，不看名字看它声明在哪个文件里。

### 层 → 职责 → 前缀

| 层 | 前缀 | 管什么 | 不管什么 |
| --- | --- | --- | --- |
| 入口 Controller | `Ctrl` | 读请求、校验参数、把领域错误映射成协议错误码 | 写业务规则；碰存储；跨多次 Service 编排 |
| 业务 Service | `Srvc` | 判断该不该允许；组织一次完整业务动作 | 认识协议细节；拼存储路径；直接碰外部资源 |
| Manager | `Mgr` | 收口外部资源：文件监听、配置热加载、模型 API | 判断该不该调；把业务规则藏进降级分支 |
| 存储 Dao | `Dao` | 单源原始读写、路径安全、原子写 | 任何业务判断 |

声明在上述四个单元里的**类**必须带对应前缀：`SrvcSpaces`、`SrvcSettings`、`MgrSpaceRuntime`、`MgrLlmClient`。

- 实体与值对象**不加**前缀（`SpaceInfo`、`ChatTurn`）——它们不划层，也没有依赖规则可挂
- 契约 / 类型单元里的类型**不加**前缀
- 前缀只加在**类型名**上，变量名照旧：`const spaces: SrvcSpaces = ...`
- 目前的 ctrl 与 dao 只导出函数，没有类，所以还没有 `Ctrl*` / `Dao*` 实例

## 错误处理

存储层与业务层**不抛协议错误**，只说「出了哪类问题」。词汇表在 `src/server/kernel/errors.ts`，全部继承 `DomainError`：

| 错误 | 什么时候抛 |
| --- | --- |
| `NotFoundError` | 要读的东西不存在 |
| `ConflictError` | 要写的位置已被占用 |
| `InvalidPathError` | 路径本身不合法：空、相对、含非法字符、以 `.` 开头 |
| `PathEscapeError` | 路径合法，但越出了允许的根目录 |
| `InvalidInputError` | 输入不满足操作要求：缺字段、格式不对、规则不允许这么改 |

**入口层不抛，只映射。** 全项目唯一的映射表是 `kernel/http.ts` 的 `statusOf`：`NotFoundError`→404、`ConflictError`→409、`PathEscapeError`→403、`InvalidPathError`/`InvalidInputError`→400、其余→500。换一个入口（MCP、CLI）就换一张表，领域层一行都不用动。

```ts
// 存储层：只说事实
if (!existsSync(absolute)) throw new NotFoundError(`文件不存在：${rel}`);

// 入口层：翻译成协议码，不重新判断业务规则
const status = statusOf(error);
sendJson(res, status, { error: message });

// 入口层自己的参数校验（HTTP 请求形状不对），用 httpError
if (!rel) throw httpError(400, '缺少 path 参数');
```

由此得到两条**不得违反**的约束：

- `dao.ts` / `service.ts` / `manager.ts` 不得 import `kernel/http`
- 「什么情况算 409」这类判断只写在领域层；入口层的 catch 里不许出现业务 if
